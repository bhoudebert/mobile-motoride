# 0030. The Android release is built and signed by GitHub Actions

- Status: accepted
- Date: 2026-10-20

## Context

`android/` is generated by `expo prebuild` and ignored (ADR 0002), and the generated Gradle signs the release build with the
debug key. The author wants the Android files for Google Play without an Expo account, as in another project of theirs
(a local Gradle build with a keystore). Play takes an App Bundle, not an APK, and refuses a `versionCode` it has seen.

## Decision

- `app.config.ts` takes `version` from `package.json` (release-please bumps it) and computes the Android `versionCode`
  from it (`src/core/release.ts`, tested).
- An Expo config plugin (`plugins/`) edits the generated `app/build.gradle`: a `release` signing config read from
  environment variables or `android/keystore.properties`, used by the release build type. With no key a development build
  still works; with `MOTORIDE_REQUIRE_RELEASE_SIGNING` set (CI) a missing key stops the build. The edit refuses to apply
  to a Gradle file it does not recognise, so an Expo upgrade cannot silently ship a debug-signed release.
- `npm run build:android` regenerates `android/` and builds the `.aab` and the `.apk`.
- A reusable workflow builds them on the release (called by `release.yml` after release-please, because an event made
  with the workflow's own token starts no other workflow) and attaches `motoride-X.Y.Z.aab` and `.apk` to the GitHub
  release. The upload key is four repository secrets; without them the job warns and builds nothing.
- Uploading to Play stays manual.

## Consequences

No Expo account or paid service for Android; the signing key is the author's and never in the repository. The build runs
on GitHub's Ubuntu runners and takes minutes. An Expo SDK upgrade may change the generated Gradle: the plugin's test and a
failing build say so. iOS is not covered (it needs macOS: EAS or a Mac), see `docs/SHIPPING.md`.

## Alternatives considered

EAS Build for Android too: less to maintain, but an account, a quota, and the key held by a third party. Committing
`android/`: loses the regenerate-from-config property (ADR 0002). Signing by hand on a laptop: works, forgotten before the
next release.
